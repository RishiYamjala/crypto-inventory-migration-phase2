## The thesis

**Inventory the cryptography, prioritize the migration, then measure—not guess—how processor geometry changes a quantum workload.**

```text
┌────────────────────────┐       ┌─────────────────────────────┐
│ Classical crypto       │       │ Quantum architecture study  │
│ inventory              │       │                             │
│ risk score → phase     │       │ same Grover circuit         │
│ migration plan         │       │ A → transpile → execute     │
│                        │       │ B → transpile → execute     │
└────────────┬───────────┘       └──────────────┬──────────────┘
             │                                  │
             └──────────────┬───────────────────┘
                            ▼
                 evidence-based Phase 1 report
```

## What is inside

### Part A — Crypto inventory → migration plan

- Ten-row sample inventory in `data/raw/inventory.csv`
- Auditable vulnerability, sensitivity, lifespan, and risk scoring tables
- HNDL detection for long-lived public-key assets in exposed usages
- NIST-aligned recommendations using ML-KEM, ML-DSA, SLH-DSA, AES-256, AES-256-GCM, SHA-256, and SHA-3
- Phase-based migration prioritization

### Part B — Controlled A/B benchmark

- Three-qubit Grover search for marked state `101`
- Two iterations; all qubits measured
- Identical A/B conditions: `4096` shots, optimization level `1`, seed `42`, and shared noise model
- Measured success probability, uncertainty, depth, two-qubit gates, SWAP estimate, physical qubits, total operations, runtime, and ideal reference

## PS-P2 scanner evaluation

The Phase 1 guide asks for a static-analysis scan of a public open-source repository and reports of precision, recall, and scanner execution time. The local synthetic fixture is a safe demo, **not** that evaluation. This repository now includes a reproducible runner for a public GitHub repository:

```powershell
python scripts/evaluate_public_repo.py --repo psf/requests --ref v2.34.2
```

It writes candidate findings to `results/tables/public_repo_scan_findings.csv` and a summary to `results/tables/public_repo_scan_summary.json`. Scanner execution time is measured separately from download time. The runner writes a review template to `results/tables/public_repo_ground_truth_template.csv`; copy that generated file to `data/raw/psp2_ground_truth.csv` before annotating it. Annotate every detected path/algorithm pair and add any true findings the scanner missed. Keep the generated `repository` and `ref` columns unchanged, then set `is_present=true/false` and `reviewed=true` for every candidate. Add missed true findings with the same repository/ref values. The evaluator rejects labels from a different repository or revision. Precision and recall intentionally remain **pending** until the full audit scope is reviewed:

```powershell
Copy-Item results/tables/public_repo_ground_truth_template.csv data/raw/psp2_ground_truth.csv
# After manually completing the audit:
python scripts/evaluate_public_repo.py --repo psf/requests --ref v2.34.2 --ground-truth data/raw/psp2_ground_truth.csv --ground-truth-complete
```

Do not report unreviewed candidate counts as precision or recall. The scanner is regex-based and can miss cryptographic uses that do not match its current patterns. Review the source evidence and record both true positives and false positives, plus any missed true findings, before claiming evaluation metrics.

## Quick start

Use Python 3.11 or 3.12 in a fresh virtual environment. From Windows PowerShell:

```powershell
git clone https://github.com/RishiYamjala/crypto-inventory-migration-planner.git
cd crypto-inventory-migration-planner
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pytest -q
python check_phase1_submission.py
jupyter notebook main.ipynb
```

If PowerShell cannot find `py -3.12`, install Python 3.12 first or use `python -m venv .venv` with a supported Python version. If activation is blocked by your machine's PowerShell policy, open Command Prompt and run `.venv\Scripts\activate.bat` instead.

On macOS/Linux, replace the environment creation and activation commands with:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

In Jupyter, choose **Kernel → Restart Kernel and Run All Cells**. To execute the notebook headlessly:

```bash
jupyter nbconvert --to notebook --execute main.ipynb --output executed_main.ipynb --ExecutePreprocessor.timeout=600
```

The artifact checklist checks files and basic expected fields; it does not certify scientific validity. `python validate_processors.py` checks the participant-defined models' internal consistency and required settings, not hardware authenticity.

## Reproducibility controls

| Control | Value |
|---|---:|
| Shots | `4096` |
| Seed | `42` |
| Transpiler optimization level | `1` |
| Marked state | `101` |
| Grover iterations | `2` |
| One-qubit depolarizing error | `0.001` |
| CX depolarizing error | `0.005` |
| Readout error | `0.01` |

The SWAP value is explicitly an **estimate**: extra compiled two-qubit gates divided by three.

The JSON coupling maps are documented as **undirected physical couplings** and expanded into both directions for Qiskit transpilation. This is an explicit simulator assumption, not a claim about hidden hardware directionality. The Aer noise model is also a simplified research assumption: one-qubit depolarizing noise applies to listed non-two-qubit basis operations, CX-family depolarizing noise applies to listed two-qubit basis operations, and the readout error applies to measurements. The current settings follow the guide's illustrative values (CX `0.005`, readout `0.01`); they are not official calibration data.

## Why the classical and quantum parts belong together

The inventory planner answers: **which cryptographic assets should an organization migrate first, and why?** The Grover experiment answers a different Phase 1 question: **how does processor architecture change execution of the same quantum solution?** The benchmark is included because the challenge requires an A/B architecture comparison; it is not a measurement of an organization's real RSA/ECC attack cost and should never be presented as one.
